# 4.0.6 — 台本のエラーに具体的な修正方法を示す

4.0.6 は、エラー画面の「対処方法」の変更だけが入っています。台本、保存データ、作品の保存形式、ブロックは変わりません。

## 原因不明に落ちる範囲を狭める

4.0.5 までのエラー画面は、カメラ・素材・式・YAML・Schema など十数系統のコードにだけ個別の案内を持ち、それ以外はすべて「原因を特定できませんでした。／分かっている場所を確認してください」になっていました。4.0.6 では、コードごとの題・説明・対処を表に持ち、`src/dsl4` が出す 476 個のコードすべてに具体的な修正方法を割り当てました（Issue #1094）。

- 表は `src/dsl4/platform/runtime-error-remedies.ts` にあり、上から順に最初に一致したものを使います。個別のコードは、属する系統より前に置きます。
- 台本の書き方の誤りが、実行時の失敗の文言に吸われていたものを分けました。たとえば素材の `file` に絶対パスを書いた `K4-ASSET-001` は、「素材を準備できませんでした」ではなく「素材のファイル指定を直してください」と、相対パスへの書き換えを案内します。
- 例
  - `K4-INCLUDE-CYCLE`: 取り込みの順序をたどって、どこか1か所の `include` を外す
  - `K4-ID-INVALID`: 名前から空白と記号を外し、日本語は Unicode NFC で入力し直す
  - `K4-KEY-UNSUPPORTED`: キーを `KeyA`、`Digit1`、`ArrowLeft` のような名前で書く
  - `K4-VIDEO-AUTOPLAY`: 画面をタップしてから再生し直すか、動画を `muted` にする
  - `K4-SOURCE-UTF8-001`: 台本を UTF-8（BOM なし）で保存し直す

### 変わらないもの

- 原因を特定できない失敗は、これまでどおり「原因を特定できませんでした」と明示します。確認する場所・直前の変更の切戻し・診断情報の受渡しという、原因によらず有効な手順を番号付きで示すだけです。
- 照合はコードと例外名だけで行います。未知のエラーの英語メッセージ本文から、通信障害や台本の誤りと断定することはありません。
- エラーコード、元のメッセージ、発生位置、「技術的な詳細」の内容、診断情報のコピー対象は変わりません。

## 切り戻し

4.0.5 の npm パッケージ、Standard SB3、Player に戻してください。台本や保存データの変換は不要です。
