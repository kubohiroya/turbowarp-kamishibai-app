# 4.0.3 — ポーズ認識のモデルをサイトから取得し、SB3 を小さくする

4.0.3 には三つの変更が入っています。

1. ポーズ認識のモデル（PoseNet）を作品に埋め込まず、サイトから取得して全作品で共有する
2. asset-cache 0.9.2：IndexedDB を使う部品をページ全体で一つにまとめる
3. 再生用ランタイムから編集用の schema を外す

## 1. ポーズ認識のモデルをサイトから取得して共有する

ポーズ認識に使う PoseNet のモデル（約 5.1 MB、Base64 では約 6.8 MB）を、作品の `project.json` に埋め込むのをやめました（Issue #1162）。作品はポーズ認識を最初に始めるときに、紙芝居アプリのサイト（GitHub Pages）からモデルを取得します。

- **SB3 が小さくなります。** Standard SB3 は 7,858,420 バイト（4.0.2）から 2,729,142 バイトになりました。展開後の `project.json` も約 15.3 MB から 8,541,406 バイトになり、16 MiB の上限まで余裕ができます。
- **モデルは全作品で共有されます。** モデルのファイルは、中身の SHA-256 をそのまま名前にした URL（`posenet/sha256-<hex>`）で配っています。ブラウザの Cache Storage にこの URL で保存するので、一度取得すれば、ほかの作品でもダウンロードせずに使えます。
- **中身は必ず検証します。** 作品が受け取るモデルは、Teachable Machine のパッケージに固定された SHA-256 と大きさで検証します。一致しないファイルは使わず、Cache Storage にも保存しません。保存済みのファイルが壊れていた場合は、消して取得し直します。
- **取得に失敗しても、次に認識を始めるときにやり直します。** エラーは `K4-POSENET-REMOTE-002`（取得できない）または `K4-POSENET-REMOTE-003`（中身が一致しない）として、ほかのアセットのエラーと同じように表示されます。

### ネットワークのない会場で使う場合

Standard SB3 と、asset profile を指定せずに CLI でビルドした作品は、ポーズ認識を最初に使うときにネットワークが必要になります。ネットワークのない会場で使う作品は、asset profile で `network: forbidden` を指定して CLI でビルドしてください。この場合は、これまでどおりモデルを `project.json` に埋め込みます。

一度ネットワークのある場所で同じブラウザからポーズ認識を使っていれば、モデルは Cache Storage に残っているので、その後はオフラインでも使えます。ただし、ブラウザがストレージを消すことがあるので、会場での利用は `network: forbidden` のビルドを推奨します。

### 変わらないもの

- 4.0.2 以前に作った作品は、モデルを埋め込んだままなので、これまでどおり動きます。
- 台本の読み取り結果、診断、作品の保存形式（モデルの記述子を置く場所）は変わりません。違うのは、記述子が `encoding: 'remote'` になり、モデルのバイト列を持たないことだけです。
- Teachable Machine のパッケージは変えていません。既存の `loadFiles` の入口を使っています。

## 2. asset-cache 0.9.2

asset-cache を 0.9.2 に上げました（kubohiroya/turbowarp-asset-cache#40）。紙芝居の本体と asset-cache 拡張は、同じページでそれぞれ asset-cache の部品を持っています。0.9.2 では、IndexedDB の `tw-asset-cache` を使う部品をページ全体で一つにまとめたので、両者が同じ接続と記録を共有します。これまでは別々に開いていたため、一方で消した記録をもう一方が古いまま返したり、書き込みの世代を取り違えたりするおそれがありました。DB の名前、版、形式は変わらないので、既存の cache はそのまま読めます。0.9.2 には 0.9.1 の変更（資源の使い方を示すメタデータの追加）も含まれます。紙芝居のコードは変えていません。

## 3. 再生用ランタイムから編集用の schema を外す

再生用ランタイム（playback profile）は、これまで Plus-Editor で YAML を編集するための schema（`dsl-4-editor.schema.json`、約 150 KB）も同梱していました。台本の編集は Plus-Editor で編集用ランタイム（authoring profile）を使って行うので、再生用ランタイムからはこの schema を外しました（Issue #1162）。再生用ランタイムは約 130 KB 小さくなります。

- 配布している Standard SB3 と Player は編集用ランタイムを積んでいるので、これまでどおり schema を持ちます。
- 再生用ランタイムの作品を Plus-Editor で開いても、YAML の編集はできます。変更の内容は従来どおり台本の読み取り部品が検証します。違うのは、Editor が schema による入力補助を出さないことだけです。
- package の公開 API `./embedded-yaml` は、従来どおり既定で schema を付けます。`editorSchema: null` を渡すと外せます。

## 切り戻し

4.0.2 の npm パッケージ、Standard SB3、Player に戻してください。台本や保存データの変換は不要です。4.0.3 で作った作品を 4.0.2 のランタイムで開くと、ポーズ認識だけが `remote` の記述子を読めずに失敗します。その場合は 4.0.2 で作り直してください。

サイトの `posenet/` に置いたファイルは、4.0.3 以降の作品が参照し続けるので、切り戻した後も消さないでください。サイトのビルドは、`test/fixtures/dsl4/posenet-published-digests.json` に記録したファイルを一つでも出さないと失敗します。
