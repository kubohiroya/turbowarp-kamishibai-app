# 4.0.3 — 再生用ランタイムから編集用の schema を外す

## 変更範囲

CLI でビルドした作品が使う再生用ランタイム（playback profile）は、これまで Plus-Editor で YAML を編集するための schema（`dsl-4-editor.schema.json`、約 150 KB）も同梱していました。台本の編集は Plus-Editor で編集用ランタイム（authoring profile）を使って行うので、再生用ランタイムからはこの schema を外しました（Issue #1162）。再生用ランタイムは 6.08 MB から 5.95 MB になり、約 132 KB 小さくなります。

- 配布している Standard SB3 と Player は編集用ランタイムを積んでいるので、これまでどおり schema を持ち、大きさは変わりません。
- 再生用ランタイムの作品を Plus-Editor で開いても、YAML の編集はできます。変更の内容は従来どおり台本の読み取り部品が検証します。違うのは、Editor が schema による入力補助を出さないことだけです。
- package の公開 API `./embedded-yaml` は、従来どおり既定で schema を付けます。`editorSchema: null` を渡すと外せます。

台本の読み取り結果、診断、作品ファイルの形式は変わりません。

## 切り戻し

4.0.2 の npm パッケージ、Standard SB3、Player に戻してください。台本や保存データの変換は不要です。
