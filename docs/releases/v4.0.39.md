# 4.0.39 — 作者が宣言した broadcast の後でもセーブできる

- `broadcastMessageAndWait` に `saveSafe: true` を指定できるようにしました。そのmessageで動く Scratch の script が、セーブポイントで戻すべき状態を残さない（または後続の action で作り直す）という作者の宣言です。
  - 宣言した broadcast を実行した後でもセーブでき、復元します。復元では message を送り直さず、receiver の作用も戻しません。
  - `saveSafe` は Scratch へ渡さず、セーブの判定にだけ使います。
  - ブロックでは「命令の追加設定 JSON」に `{"arguments": {"saveSafe": true}}` として保持し、YAML とブロックの間で往復します。
- 宣言のない broadcast は、これまでどおりセーブを拒否します。拒否のメッセージで `saveSafe: true` の指定を案内します。
- custom action は TurboWarp 上の再生にまだ配線されていないため、拒否を続けます。
- 詳しくは [DSL 4.0 surface の broadcastMessageAndWait](../design/dsl-4-surface.md) と [セーブと viewport](../design/dsl-4-save-viewport.md) を参照してください。

## 互換性

`saveSafe` は省略可能で、既定では従来どおり拒否します。既存の台本はそのまま動きます。`saveSafe` を使った台本は 4.0.38 以前では読み込めません（未知の項目として検証で拒否します）。セーブデータの形式（SaveDataV1）は変わりません。4.0.38 までに作った SB3 は、それぞれに同梱されたランタイムで従来どおり動きます。
