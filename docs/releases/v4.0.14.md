# 4.0.14 — メニューの「開く」で読み込んだ台本でもキー操作を効かせる

4.0.14 では、メニューの「開く」で読み込んだ台本のキー操作を直しました。台本の書き方、保存データ、作品の保存形式、ブロック、再生の動作は変わりません。

## メニューの「開く」で読み込んだ台本でキーが効かなかった

作品のメニューの「開く」で台本（YAML）を読み込んで再生すると、Space・→・↓（`rehearsal.skipPose`・`rehearsal.skipAction`・`rehearsal.skipScene`）を押しても反応しませんでした。ポーズ待ちを飛ばせないため、ポーズが認識されないかぎり先へ進めませんでした（#1183）。作品に埋め込んだ台本では、同じキーが効いていました。

原因は、キーを受け取る要素が違っていたことです。

- 作品に埋め込んだ台本は、キーを`document`で受け取ります。
- メニューの「開く」で読み込んだ台本は、作者用プレビューのセッションで再生されます。このセッションは、キーをステージの描画用canvas（`Scratch.vm.renderer.canvas`）で受け取っていました。このcanvasはフォーカスを受け取れないため、ページで押したキーが届きませんでした。

4.0.14 では、メニューの「開く」で読み込んだ台本も、キーを`document`で受け取ります。ポインタでの送り（ステージのクリック・タップ）は、今のままステージのcanvasで受け取ります。入力欄やエディタで押したキーは、これまでどおり台本の操作には使いません。

この不具合は、turbowarp-kamishibai-samples の手児奈のワークショップを公開Plus Editorでリハーサルしたときに見つかりました。外部YAML版（作業用SB3にメニューから台本を読み込む経路）で、ポーズ待ちを飛ばせず再生が止まっていました。

## 切り戻し

4.0.12 の npm パッケージ、Standard SB3、Player に戻してください。台本や保存データの変換は不要です。4.0.12 に戻すと、メニューの「開く」で読み込んだ台本でキーが効かない状態に戻ります。

4.0.13 は、GitHub Release と npm までの公開で止まり、Pages の配信が済んでいません（#1190）。4.0.13 のエディターで組んだ作品は、サイトから再生ランタイムを取得できないため、切り戻し先には使いません。
