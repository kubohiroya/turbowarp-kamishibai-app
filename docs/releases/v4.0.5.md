# 4.0.5 — 次の場面の認識モデルを先読みし、公開の区切りに分けた作品でも裏で読み込む

4.0.5 には二つの変更が入っています。

1. 公開の区切りに分けた作品でも、認識モデルを裏で読み込む
2. 次に進む場面の認識モデルを先読みする

## 1. 公開の区切りに分けた作品でも、認識モデルを裏で読み込む

4.0.4 では、認識モデルを場面ごとに裏で読み込み、認識を始める時点で終わっていない場合だけ待つようにしました。ただし、台本を公開の区切りに分けた作品（publication segments）は別の読み込み部品を使っていたため、場面に入る時点で認識モデルの読み込みが終わるまで待っていました。4.0.5 では、こちらも同じ扱いにしました（Issue #1162）。

- 場面に入ると、その場面の認識モデルを裏で読み込み始めます。場面の表示やセリフは読み込みを待たずに進みます。
- ポーズ認識や画像認識を始める時点で読み込みが終わっていない場合だけ、終わるまで待ちます。失敗した場合は、その認識の時点でエラー（`K4-ASSET-PREPARE-001`）になります。
- 次の場面に入ったときに、まだ終わっていない読み込みのうち次の場面が使わないものを中止します。読み込み終えたモデルは、次の場面が確定した時点で、その場面が使わなければ解放します。
- `assets.background.*` のイベントは 4.0.4 と同じ名前です。

## 2. 次に進む場面の認識モデルを先読みする

4.0.4 では、認識モデルは場面に入ってから読み込み始めていました。そのため、場面に入ってすぐにポーズ認識を始める台本では、結局その場で待つことがありました。4.0.5 では、場面の認識モデルを読み込み終えたら、続けて「この場面から次に進みうる場面」の認識モデルも裏で読み込みます。

- 次に進みうる場面は、台本から次のように決めます。
  - `goto` の行き先
  - `branch` のすべての行き先
  - `poseInputToChangeScene` などの入力で場面を変える動作の、すべての行き先（`routes`）
  - 場面が最後まで進んだときの、並び順で次の場面。ただし、場面の最後の動作が場面を移す動作なら含めません。
- custom action による移動は、実行するまで行き先が分からないので含めません。
- 先読みは、その場面自身のモデルを読み終えた後に始めます。今の場面のモデルと読み込みを取り合うことはありません。
- 先読みしたモデルは、次の場面が確定するまで保持します。確定した場面とその次に進みうる場面が使わないモデルは、そこで解放します。分岐の多い場面では、行き先の数だけモデルを同時に保持することになります。
- `assets.background.start` などのイベントに `prefetch: true` が付くので、先読みを見分けられます。

### 変わらないもの

- 認識モデル以外のアセットの読み込み方、台本、診断、作品の保存形式は変わりません。
- 公開の区切りに分けていない作品の読み込み方は、2 の先読みが加わるほかは 4.0.4 と同じです。

## 切り戻し

4.0.4 の npm パッケージ、Standard SB3、Player に戻してください。台本や保存データの変換は不要です。
