# 4.0.15 — 無効区間の本体をYAMLとブロックに保持する

手児奈の教材で「この部分を使う：オフ」にしたポーズ処理が、台本へ反映して保存すると消える問題を修正します（#1198）。DSLの系列は4.0のままです。

## 専用のinvalidate書式

```yaml
- invalidate:
    condition: false
    then:
      - Sato.pose:
          steps:
            - pose: kime
              skin: sato-kime
```

`false`はオフ、`true`はオンです。静的booleanだけを受理します。オフでも本体と依存する宣言を保存し、実行時の参照解決・認識は行いません。構造・サイズ・深さは検証します。汎用の`if`とは区別します。

Schemaと生成される編集支援Schema、解釈器、ブロックとの相互変換、依存収集、builderの能力検査を更新します。旧runtimeが新書式を黙って読み飛ばさないよう、`invalidate-source-v1`の能力を検査します。詳細は[専用無効化区間](../dsl4-invalidate.md)を参照してください。

4.0.14で導入した、メニューの「開く」で読み込んだ台本でもキー操作をdocumentで受け取る修正（#1192）を含みます。さらに、その後mainへ入った、版付きauthoring runtimeとmanifestの配信（#1193）、構成する全componentの記録版を検査する修正（#1196）も含みます。

4.0.15の凍結SB3について再現性照合、lint・整形・型検査、通常259ファイル／2,528テスト、preview 59テスト、Chromium 28テスト、サイトのローカル生成、配布tarballの新規本番インストール（647 files）・CLI起動・正負DSL検証を確認しました。

全検証の最初の実行では、sandboxがローカル待受とChrome起動を拒否した2ファイル、および旧section用frontendの前提が残った1ファイルで失敗しました。前者は必要な実行権限で個別再実行し、後者は専用invalidate対応frontendとゼロ秒のソース境界を明示するfixtureへ更新して、該当ファイルの全テスト成功を確認しました。製品コードを変えて既存検査を回避していません。

手児奈の現行main構成でも、22本編シーン／42作業用シーンを内部YAML23／43文書として生成し、枠01を有効化・反映・保存・再読み込みして56無効区間と43文書を保持することを確認しました。20席すべてを有効にした場合も、認識呼び出しは0回で最後まで進みます。

承認済みの公開Plus Editorでも4.0.15の現行42シーン版を検証しました。枠01の絵・セリフ・条件を編集して個別文書へ反映し、スキップなしで最後まで再生しました。410.918秒・254フレームで完走し、ページエラーは0件でした。Editorから保存した実SB3にも56個すべてのポーズ用OFF区間と43文書が残り、CLIの複数文書package exportも成功しました。旧14／34シーン構成の4.0.1起点の互換プレビュー結果と区別して記録します。
