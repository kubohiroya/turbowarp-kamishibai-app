# 4.0.11 — 半完成の作品でremote素材のURLを編集できるようにする

4.0.11 では、教材として配る半完成の作品で、受講者が自分で用意したremote素材のURLに書き換えられるようにしました（Issue #1184）。台本の書き方、保存データ、作品の保存形式、ブロック、再生の動作は変わりません。

## 半完成の作品でremote素材のURLを編集できるようにする

ワークショップの教材は、完成していない作品として配ります。受講者は、自分でTeachable Machineのポーズモデルを作ってクラウドへ公開し、そのURLを台本のアセットブロックへ書き入れて作品を完成させます。

これまでは、この書き換えが拒否されました。エディターの「表示されている形式に変換して検証・保存」は、SB3 の asset bundle manifest に記録したremote素材と、台本（StoryDocument）が宣言するremote素材を必ず突き合わせていました。URLを変えると食い違いになり、`K4-ASSET-BUNDLE-MANIFEST-001`（`Remote asset source does not match: <素材名>`）で止まりました。URL欄を空にする道もありません。schemaがURLを必須とし、`https://` で始まる文字列を求めるためです。

原因は、作品が「まだ作られていない」か「完成している」かのどちらかである、という前提でした。保存したあとに素材が変わりうる半完成の状態が、想定から抜けていました。

4.0.11 では、既定を「編集できる」に改めます。突き合わせを行うのは、次の2つの場合だけです。

- **作者が `integrity` で固定した素材。** 固定は明示的な行為なので、宣言と記録の食い違いは改ざんとして扱い、これまでどおり拒否します。
- **完成を宣言した作品。** `build-dsl4` に `--seal-asset-sources` を付けてビルドすると、以後はすべてのremote素材を固定し、変更をエラーとします。宣言は `storyDocument.metadata.sealedAssetSources` に記録し、compiled成果物のmetadataでも保持します。

remote素材はバイト列をSB3に持ちません。固定情報のない記録は宣言の複製であり、突き合わせても守る対象がないため、既定での比較をやめても配布物の同一性は損なわれません。

## 使い方

半完成の教材を作るときは、`--seal-asset-sources` を付けずにビルドします。アセットブロックのURLには見本のURLを書いておけば、受講者がそれを自分のURLへ上書きできます。

完成した作品を配るときは、`--seal-asset-sources` を付けてビルドします。あるいは素材ごとに `integrity` を書けば、その素材だけを固定できます。

## 切り戻し

4.0.10 の npm パッケージ、Standard SB3、Player に戻してください。台本や保存データの変換は不要です。4.0.11 で作った作品は、そのまま 4.0.10 以前の作品と同じように動きます。

ただし 4.0.10 以前のエディターは、remote素材のURLの書き換えを引き続き拒否します。半完成の教材を配る運用は 4.0.11 以降が必要です。
