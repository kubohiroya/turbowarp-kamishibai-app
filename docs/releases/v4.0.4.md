# 4.0.4 — TensorFlow.js をサイトから読み込み、認識モデルを場面ごとに裏で読み込む

4.0.4 には二つの変更が入っています。

1. ポーズ認識に使う TensorFlow.js を作品に同梱せず、必要になったときにサイトから読み込む
2. 認識モデルを場面ごとに裏で読み込み、認識を始める時点で終わっていない場合だけ待つ

## 1. TensorFlow.js をサイトから読み込む

Teachable Machine 拡張は、これまで TensorFlow.js（WebGL・CPU・WebGPU・WASM の計算方式を含めて約 2.8 MB）を作品に同梱していました。4.0.4 では、作品が積む Teachable Machine 拡張を、TensorFlow.js を含まない軽い版（約 100 KB）に替えました（Issue #1162）。

- **SB3 が小さくなります。** Standard SB3 は 2,731,304 バイト（4.0.3）から 1,542,104 バイトになりました。展開後の `project.json` も 8,541,406 バイトから 4,886,798 バイトになります。
- **読み込むのは、認識モデルを使う場面に入ったときです。** タイトルや、認識を使わない場面だけを進む間は、TensorFlow.js を読み込みません。認識モデルを使う場面に入ると、モデルの準備と一緒に、紙芝居アプリのサイト（GitHub Pages）の `teachable-machine/<版>/runtime.js`（約 1.3 MB）を読み込みます。WebGPU と WASM の計算方式は、その計算方式を選んだときにだけ、同じ場所から読み込みます。
- **中身は必ず検証します。** `runtime.js` は、ビルド時に記録した SHA-384 を Subresource Integrity で指定して読み込みます。一致しないファイルはブラウザが実行しません。読み込んだランタイムの版が作品の想定と違う場合も使いません。
- **読み込みに失敗しても、次に認識を始めるときにやり直します。** エラーは `K4-TM-RUNTIME-001`（読み込めない）、`K4-TM-RUNTIME-002`（版が違う）として、ほかのアセットのエラーと同じように表示されます。
- サイトには、これまでに公開した版のランタイムを残し続けます。サイトのビルドは、`test/fixtures/dsl4/tm-runtime-published.json` に記録した版を一つでも出さないと失敗します。

### ネットワークのない会場で使う場合

asset profile で `network: forbidden` を指定して CLI でビルドした作品は、これまでどおり TensorFlow.js を作品に埋め込みます（WebGPU・WASM を含む一つのファイル、約 3 MB）。作品は埋め込んだランタイムの SHA-256 を確かめてから実行し、一致しなければ `K4-TM-RUNTIME-003` で止まります。PoseNet のモデルの扱い（4.0.3）と同じく、会場での利用は `network: forbidden` のビルドを推奨します。

## 2. 認識モデルを場面ごとに裏で読み込む

これまでは、台本が指定した認識モデルを、作品の開始時にまとめて読み込み終えるまで待っていました。モデルが多い台本ほど、タイトルが出るまで長く待つことになります。

4.0.4 では、認識モデルを作品の開始時に読み込まず、そのモデルを使う場面に入ったときに裏で読み込み始めます。場面の表示やセリフは読み込みを待たずに進みます。ポーズ認識（`pose`、`poseInputToChangeScene`）や画像認識（`imageInputToChangeScene`）を始める時点で読み込みが終わっていない場合だけ、終わるまで待ちます。

- 読み込みに失敗した場合は、その認識を始める時点でエラーになります。場面に入った時点では止まりません。
- 場面を離れると、まだ終わっていない読み込みは中止します。
- `assets.background.start`、`assets.background.ready`、`assets.background.error`、`assets.background.wait.start`、`assets.background.wait.end` のイベントで、裏の読み込みと待ちを追えます。`turbowarp-kamishibai audit-dsl4-assets` の出力には、場面ごとの `background` が加わります。

### 変わらないもの

- 認識モデル以外のアセット（画像、音声など）の読み込み方は変わりません。
- 公開を区切りに分けた作品（publication segments）では、認識モデルを開始時には読み込まなくなりましたが、場面に入る時点で読み込み終わるまで待ちます。裏で読み込む扱いは今後の課題です。
- 台本、診断、作品の保存形式は変わりません。

## 切り戻し

4.0.3 の npm パッケージ、Standard SB3、Player に戻してください。台本や保存データの変換は不要です。4.0.4 で作った作品は、4.0.3 で作り直してください。

サイトの `teachable-machine/` に置いたファイルは、4.0.4 以降の作品が参照し続けるので、切り戻した後も消さないでください。
