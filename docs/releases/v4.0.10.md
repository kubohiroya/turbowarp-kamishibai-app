# 4.0.10 — エディターで作った作品に再生用のランタイムを積む

4.0.10 では、エディターの「配布用SB3を作る」で作った作品を小さくしました（Issue #1162）。台本、保存データ、作品の保存形式、ブロック、再生の動作は変わりません。

## エディターで作った作品に再生用のランタイムを積む

紙芝居のランタイムには、制作に使う authoring 用と、観る人向けの playback 用の二つがあります。

- 配布している Standard SB3（`kamishibai-<版>.sb3`）は、Plus-Editor で開いて制作する道具です。台本ファイルを開く機能、配布用SB3を作る機能、ブロックのアイコン表示、エディターでのデバッグ、YAML 編集用の schema を使うので、authoring 用のランタイムを積んでいます。これは変わりません。
- CLI で作った作品は、もともと playback 用のランタイムを積んでいます。

これまで、エディターの「配布用SB3を作る」で作った作品は、エディターのプロジェクトをそのまま写すため、authoring 用のランタイムを持っていました。観る人には要らない制作用の部品の分だけ大きくなっていました。

4.0.10 では、エディターでのビルドが、同じ版の playback 用のランタイムを紙芝居アプリのサイト（GitHub Pages）の `runtime/<版>/kamishibai-playback.js` から取得し、作品のランタイムと差し替えます。

- **作品が小さくなります。** 4.0.10 のランタイムは authoring 用が 3,736,310 バイト、playback 用が 3,291,367 バイトです。差の 444,943 バイト（`project.json` の中では Base64 で約 593 KB）が減ります。
- **中身は必ず検証します。** authoring 用のランタイムは、ビルドした時点で playback 用のランタイムの大きさと SHA-256 を記録しています。取得したファイルが一致しなければ使いません。
- **取得できなくても作品は作れます。** ネットワークがない、サイトに届かない、検証に失敗した、といった場合は、これまでどおり authoring 用のランタイムを積んだ作品を作ります。作品の動きは同じで、大きさだけがこれまでと同じになります。このときは、コンソール（デバッガーを開いていればその Logs）に警告を出します（`K4-PLAYBACK-RUNTIME-001`）。
- 作品はランタイムを `project.json` の中に持つので、作品を開くときにサイトへは取りに行きません。サイトを使うのは、エディターでビルドするときだけです。
- サイトには、4.0.10 以降に公開した版の playback 用のランタイムを残し続けます。サイトのビルドは、今の版のファイルをこのリポジトリから、それより前に npm へ公開した版のファイルをその版の npm パッケージから取り出して置きます。npm に公開していない版は置きません。

## 切り戻し

4.0.9 の npm パッケージ、Standard SB3、Player に戻してください。台本や保存データの変換は不要です。4.0.10 のエディターで作った作品は、そのまま 4.0.9 以前の作品と同じように動きます。

サイトの `runtime/` に置いたファイルは、4.0.10 以降のエディターが参照し続けるので、切り戻した後も消さないでください。
