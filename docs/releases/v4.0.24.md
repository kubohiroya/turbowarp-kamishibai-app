# 4.0.24 — include を正式な機能にし、章（segment）を廃止

- `include` を正式な機能にしました。台本が `include` を宣言していれば、フラグや CLI の指定なしに取り込んだファイルと合成します。宣言していない台本は従来どおり単独で読み、成果物に入る本文も変わりません。ファイルをまたぐ場面の移動も `goto` で行えます。
- CLI の `--enable-source-includes` は不要になりました。既存のスクリプトのために受理しますが、効果はありません。`--max-source-files`・`--max-total-source-bytes`・`--max-include-depth` は任意になり、省略時は 64 ファイル・4 MiB・深さ 32 を使います。
- 開発用プレビューは、台本が `include` を宣言した時点から取り込んだファイルの変更にも反応します。
- 章（segment）を廃止しました。`gotoSegment`（「台本の区切り [SEGMENT] へ移る」）ブロックと DSL の命令、`publication.json` による複数章の作品、関連する公開 API を削除しました。台本の分割は `include`、移動は `goto` で行います。経緯は [segment・publication の廃止](../design/dsl-4-segment-retirement.md) を参照してください。

## 互換性

- `gotoSegment` を使う台本と `publication.json` の作品は読み込めなくなります。配布済みの publication 形式の作品はありません。
- feature flag の `dsl4SourceIncludes` は受理しますが無視します。
- npm パッケージから publication の API（`createDsl4PublicationRuntimeHost`、`validateDsl4PublicationManifest`、`createDsl4AssetGroupLifecycle` など）を削除しました。

## 受け入れ基準と切り戻し

旧版を使用する場合は npm で `4.0.23` を明示します。
